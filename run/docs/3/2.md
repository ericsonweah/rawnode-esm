## Overview (what’s fixed)

* **ERR_PARSE_ARGS_UNKNOWN_OPTION** for `--debug-walk` is caused by `parseArgs()` running in **strict** mode with no declaration for that flag.
* You also pass `--target .` (singular), while your current `options` declare **`targets`** (plural). That would be the **next** unknown‑option failure after `--debug-walk`.

This patch:

1. **Declares** `--debug-walk` and `--target` in the CLI schema (keeps strict parsing on).
2. **Implements** `--debug-walk` output (non‑blocking, low‑noise) at the runner level.
3. **Accepts roots** from **positionals**, `--target`, or `--targets` (in that order, deterministic).
4. Leaves everything else unchanged (progress UI, reports, compare mode, etc.).

---

## Plan (steps & risk)

* **Low risk**: Only adds two option entries and four tiny, well‑scoped code paths (roots derivation, logging, job scheduling line).
* **Deterministic**: No time/locale variance added; new logging gated behind `--debug-walk`.
* **No behavior change** unless the new flags are used.

---

## Decisions

* Keep `parseArgs` **strict** (so typo’d flags fail fast), but **declare** both `--debug-walk` and `--target` so they’re recognized.
* `--debug-walk` prints **what the runner schedules** (roots/jobs). We don’t spam per‑file traversal inside workers; that would belong in worker‑side debugging (we can add a worker flag later if desired).
